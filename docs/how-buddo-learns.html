Buddo · training notes

How Buddo learns

Buddo is a 3.46-million-parameter language model built from nothing: no Ollama, no Hugging Face, no pretrained weights. This page shows everything that goes into it: the data, the exact text it reads, how training runs, and an exam that runs its code to see what actually works.

01 · Pipeline

From source code to your phone

    02 · The "system prompt"

    Buddo has no system prompt

    Big chatbots get a hidden paragraph of instructions before every chat. A model this small can't follow written instructions, so Buddo has none. Its personality and its habits come entirely from its training examples. What it actually reads is one long stream of tokens, with three special markers that say who is talking:

    exactly what the model sees
    <|user|> your message starts <|bot|> Buddo's reply starts <|end|> reply is finished

    Each grey chip is one token from Buddo's own tokenizer: 4,096 word pieces learned from Python code (byte-pair encoding). Common chunks like function are one token; rarer words get split, like re + verse. When you send a message, the app builds this stream from the whole chat (up to 20,000 tokens), and Buddo predicts the next token again and again until it produces <|end|>.

    Where its personality comes from

    These hand-written replies are mixed into training many times. Buddo learned "who it is" from them.

    03 · Training data

    What Buddo reads

    Training happens in two phases. Pretraining teaches Python itself by reading lots of real code. Fine-tuning teaches the back-and-forth: a request goes in, working code comes out.

    04 · Training runs

    Watching it learn

    Loss measures how surprised the model is by the next token: lower means better predictions. Every step, the model reads a batch of 48 snippets of 256 tokens, measures its loss, and nudges all 3.46M numbers slightly to do better (backpropagation with the AdamW optimizer). Validation loss is measured on text it never trains on, so it shows real learning rather than memorization.

    05 · The exam

    Does the code actually work?

    Before training, 1 in 8 of the generated programs were locked away. Buddo never sees them. For the exam, Buddo gets each one as a request, its answer runs in a sandbox, and it passes only if the code works on real test inputs.

    06 · The ceiling

    Why it can't be 1000× smarter (yet)

    A model's smarts mostly scale with the compute spent training it. Buddo trained on 4 CPU cores. Here's how that compares to GPT-3, the model behind the first ChatGPT. The scale is logarithmic: every gridline is 10× more.

    That's why Buddo gets better through better data (verified, varied tasks) instead of size. To make a real jump, these are the levers, in order of impact:

    • A GPU. Even a free cloud GPU trains about 50–100× faster than these 4 cores, which buys a ~10× bigger model trained on far more code.
    • More verified tasks. Every new generator family in model/generators.py teaches a new pattern, and the exam score tells us if it worked.
    • Longer pretraining. Buddo has read each line of code about once; a few more passes keep lowering the loss.
